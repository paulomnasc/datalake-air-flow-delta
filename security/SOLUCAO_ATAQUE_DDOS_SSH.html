Solução Concluída Zero Alteração em Código-Fonte Incidente DDoS / Brute Force Hetzner Cloud & Docker

Mitigação de Ataque de Força Bruta & Blindagem de Servidor

Guia operacional e registro técnico da resolução de instabilidade severa, quedas de SSH e travamentos no ambiente de produção.

Servidor / Host ubuntu-16gb-nbg1-2 (Hetzner)
IP Público 46.224.156.251
Stack Afetada Docker (Airflow, MinIO, DBs) + SSH
Tipo de Intervenção Infraestrutura, Kernel e Firewall

1Diagnóstico da Causa Raiz

A instabilidade que causava a indisponibilidade do servidor, desconexões no SSH e sensação de ataque DDoS teve três causas raízes simultâneas diagnosticadas:

🚨 1. Ataque de Força Bruta SSH Massivo

Robôs mundiais (IPs identificados: 197.253.54.22, 27.72.195.145, 177.126.90.235, etc.) tentavam invadir a porta 22 a cada segundo com usuários falsos (blockchain, crypto, ubuntu). Esse fluxo saturou o limite de conexões simultâneas do SSH (MaxStartups 10), descartando conexões legítimas.

⚠️ 2. Falta Crítica de Memória Swap (0B)

O servidor possuía 16GB de RAM e zero de Swap configurado. Ao rodar a stack completa de Docker (Airflow, Spark, Postgres, Metabase), qualquer pico momentâneo de memória levava o kernel a congelar a máquina por falta de margem de escape.

🌐 3. Bloqueio de ICMP / MTU Black Hole

Ao ativar o Firewall na Hetzner liberando apenas portas TCP, o tráfego ICMP foi bloqueado. Isso impediu o Path MTU Discovery na rota Brasil ↔ Alemanha, fazendo com que pacotes grandes de troca de chave (KEX) fossem descartados, resultando em kex_exchange_identification: timed out.

Evidência do Flagrante:
O comando systemctl status ssh capturou o daemon em esgotamento: sshd: [listener] 2 of 10-100 startups e rejeitando senhas a cada fração de segundo. Logo após a instalação do Fail2ban, 274 ataques foram barrados e 6 IPs foram banidos instantaneamente.

2Passo a Passo de Ações Executadas

Fase 1: Blindagem de Memória com Swapfile de 4GB

Criou-se uma reserva de memória para absorver picos de uso do Docker sem congelar o kernel:

# 1. Aloca arquivo de 4GB e aplica permissões de segurança
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile

# 2. Formata e ativa o swap
sudo mkswap /swapfile
sudo swapon /swapfile

# 3. Torna persistente após reinicializações
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 4. Ajusta a tendência de troca para poupar I/O (usar apenas se RAM > 90%)
sudo sysctl vm.swappiness=10
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf

Fase 2: Instalação e Ativação do Fail2ban

O Fail2ban inspeciona o journal do sistema e adiciona regras dinâmicas de DROP no firewall do Linux para qualquer IP com tentativas repetidas de falha de autenticação:

apt-get update
apt-get install -y fail2ban
systemctl enable --now fail2ban

Fase 3: Aumento de Capacidade do Daemon SSH (Evitar Fila Cheia)

Aumentou-se o limite de conexões não autenticadas simultâneas permitidas pelo OpenSSH para impedir que ataques saturem o daemon:

# Aumenta o limite para 50 conexões iniciais (padrão era 10)
echo "MaxStartups 50:30:100" >> /etc/ssh/sshd_config
systemctl restart ssh

Fase 4: Resolução de Lentidão no Handshake SSH (Reverse DNS)

Desativação de checagens reversas de DNS que adicionavam 15 a 30 segundos de atraso a cada nova conexão: 

sudo sed -i 's/^#*UseDNS.*/UseDNS no/' /etc/ssh/sshd_config
sudo sed -i 's/^#*GSSAPIAuthentication.*/GSSAPIAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh

3Configuração Definitiva do Firewall (Hetzner Cloud)

Para evitar que os ataques sequer cheguem à máquina, as regras de firewall na Hetzner devem ser configuradas na aba Firewalls > firewall-1 > Rules e aplicadas na aba Resources:

Protocolo Porta Origem (Source IPs) Finalidade / Motivo
ICMP - Any IPv4, Any IPv6 Crítico Resolve o Path MTU Black Hole e permite ping de diagnóstico
TCP 22 Seu_IP/32 ou Any IPv4 SSH (idealmente restrito ao seu IP residencial para 100% de blindagem)
TCP 80 Any IPv4, Any IPv6 HTTP Web / Desafio Let's Encrypt
TCP 443 Any IPv4, Any IPv6 HTTPS Seguro (Nginx Gateway)
TCP 28083 Any IPv4 Airflow Webserver
TCP 9000 Seu_IP/32 Portainer (Restringir acesso externo ao painel administrativo)
Portas Internas Blindadas: As portas do MySQL (23306), PostgreSQL (25432, 25433), Redis (26379) e MinIO (29001/29002) NÃO devem estar no firewall externo. Os contêineres Docker se comunicam internamente via rede privada airflow_net sem necessidade de exposição à internet pública.

4Comandos Úteis de Auditoria e Manutenção

1. Verificar IPs Atualmente Banidos pelo Fail2ban:

fail2ban-client status sshd

2. Desbanir um IP (ex: caso seu IP seja bloqueado por engano):

fail2ban-client set sshd unbanip SEU_IP_AQUI

3. Ver o Status em Tempo Real da Memória e Swap:

free -h

4. Ver os Contêineres em Execução e Portas:

docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

5. Iniciar Serviços que Estiverem Parados:

docker start spark spark-worker datalake-air-flow-delta-airflow-worker-1

5Checklist de Sucesso e Estabilidade

✅ Zero Código Alterado: Nenhuma linha da aplicação Python, Airflow ou CodeIgniter precisou ser modificada.
✅ Memória Swap Ativa: 4GB adicionados como proteção contra picos de carga.
✅ Defesa Ativa Contra Força Bruta: Fail2ban banindo agressores em tempo real.
✅ Conexões SSH Desafogadas: MaxStartups ampliado e latência de DNS desativada.
✅ Roteamento de MTU Desbloqueado: Conexões internacionais estáveis sem congelamento.

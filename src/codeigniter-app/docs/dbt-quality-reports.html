📊 Relatórios de Qualidade de Dados (Data Quality) Integrados no dbt

Esta seção documenta a arquitetura de **Data Quality Observability** integrada nativamente ao fluxo de compilação do **dbt (Data Build Tool)** do projeto. Esta solução valida métricas, regras de negócio e volumes entre a base de origem e o destino final do DW, apresentando os resultados diretamente no Console e na interface de documentação do dbt Docs para os analistas e usuários de UX.

Funcionamento Automático: Toda vez que um usuário clica em dbt Run no editor de código da interface web, a validação é executada no fim do processo e injetada de forma invisível nos metadados.

🏗️ Arquitetura e Fluxo de Execução

O fluxo de processamento funciona de maneira encadeada dentro do container docker do dbt:

  1. dbt Run: Compila e grava os modelos SQL no PostgreSQL analítico (datalake_bi).
  2. dbt Docs Generate: Gera a documentação do projeto e cria os arquivos manifest.json e catalog.json em target/.
  3. Validador (Python): Executa o script dbt_validation_report.py, que realiza consultas analíticas de auditoria cruzando a origem (northwind) com o destino (datalake_bi).
  4. Injeção de Metadados: O script atualiza o campo description dos nós do dbt dentro de target/manifest.json, inserindo tabelas comparativas detalhadas em Markdown e LaTeX.
  5. Publicação na UX: O log do terminal exibe os relatórios formatados em formato limpo, e a interface gráfica do dbt Docs (carregada via iframe na UX) renderiza os relatórios completos e formatados com equações matemáticas.

📐 Regras de Qualidade e Mapeamento de Tabelas

O validador realiza auditorias diferenciadas com base nas entidades processadas:

1. Validação de Fato (fato_sales)

Compara e valida a integridade da tabela de fatos principal:

  • Volumetria: Compara a quantidade total de linhas contra o banco de origem (order_details).
  • Chaves Nulas: Garante que nenhuma chave primária (SK) ou estrangeira (FK) está nula.
  • Duplicidade: Confirma que não existem surrogate keys repetidas.
  • Auditoria de Cálculos: Recalcula linha a linha o valor bruto e líquido e compara com o destino para garantir 100% de exatidão nas fórmulas:
    • receita_bruta = quantidade * preco_unitario
    • receita_liquida = quantidade * preco_unitario * (1 - desconto)

2. Validação de Dimensões (dim_customers, dim_products, dim_employees, dim_categories)

Garante que a carga dimensional ocorreu sem corrupção:

  • Match de Volumetria: Compara a contagem total de registros da dimensão contra sua tabela original no OLTP.
  • Integridade de Chaves: Identifica chaves primárias duplicadas ou registros com SKs nulas.

3. Suporte Genérico (Fallback)

Para qualquer outro modelo customizado criado pelo usuário do dbt, o sistema de validação aciona uma auditoria genérica automatizada. Ele calcula o total de registros e integridade estrutural no banco de destino analítico, gerando relatórios de volumetria automaticamente sem interromper a pipeline.

#### 📐 Regras de Cálculo Aplicadas
* **receita_bruta** = quantidade * preco_unitario (Multiplicação direta de quantity e unit_price)
* **receita_liquida** = quantidade * preco_unitario * (1 - desconto) (Valor bruto aplicando o redutor de desconto)

#### 🧮 Exemplo Prático de Cálculo (Com Dados Reais do Banco)
Auditamos o seguinte registro real para demonstrar como as colunas calculadas foram geradas:
* **Quantidade Vendida (`quantidade`)**: 35 unidades
* **Preço Unitário (`preco_unitario`)**: R$ 42.40
* **Percentual de Desconto (`desconto`)**: 15% (fração: 0.15)

**Passo a Passo do Cálculo:**
1. **Receita Bruta**:
   Receita Bruta = Quantidade * Preço Unitário
   Receita Bruta = 35 * R$ 42.40 = R$ 1484.00
   *(Valor armazenado no destino: R$ 1484.00 - ✅ Confirmado)*

2. **Receita Líquida**:
   Receita Líquida = Receita Bruta * (1 - Desconto)
   Receita Líquida = R$ 1484.00 * (1 - 0.15) = R$ 1484.00 * 0.85 = R$ 1261.40
   *(Valor armazenado no destino: R$ 1261.40 - ✅ Confirmado)*

🛠️ Como Estender as Validações

O arquivo de validação está localizado em dbt/analytics/dbt_validation_report.py no repositório de templates. Para adicionar auditorias de regras de negócio personalizadas para novas tabelas:

  1. Abra o arquivo dbt_validation_report.py.
  2. Adicione um novo bloco condicional verificando se a nova tabela existe no destino: 
    if 'fato_financeiro' in dest_tables:
    # 1. Faça as consultas no banco dest_db e src_db usando conn.sql()
    # 2. Crie a string markdown com os comparativos e cálculos
    # 3. Guarde o relatório no dicionário: reports['fato_financeiro'] = report
  3. Ao rodar o dbt, o script automaticamente aplicará as novas regras e as integrará na interface de usuário.

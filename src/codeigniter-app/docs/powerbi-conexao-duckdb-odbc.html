0. Geração do Arquivo de Dados (.duckdb)

O arquivo de banco de dados deve ser gerado antes da configuração do ODBC.

⚠️ Pré-requisito: Certifique-se de que o duckdb.exe está no PATH do Windows

Para verificar ou adicionar o DuckDB ao PATH:

  • Vá em Variáveis de Ambiente > Path e adicione a pasta onde o duckdb.exe está localizado
  • Reinicie o PowerShell para aplicar as mudanças

No terminal (PowerShell), execute o comando para criar o arquivo físico onde os dados do Airflow serão armazenados:

duckdb datalake_airflow.duckdb

⚠️ Importante: O comando abre um shell interativo do DuckDB. Para sair e criar o arquivo, digite:

.quit

Ou pressione Ctrl + D. Isso encerrará o shell e salvará o arquivo datalake_airflow.duckdb na pasta atual.

❌ Se o arquivo não for criado, tente a alternativa:

No terminal (PowerShell), certifique-se de que está executando em uma pasta com permissão de escrita (evite pastas protegidas como Program Files). Depois execute:

echo "SELECT 1;" | duckdb datalake_airflow.duckdb

Este comando cria o arquivo de forma mais confiável no Windows e não abre o shell interativo.

0.1 Popular o Arquivo com Dados do PostgreSQL Remoto

Este é o passo CRÍTICO que faltava! O arquivo .duckdb está vazio, agora vamos copiá os dados do PostgreSQL para ele.

✅ Pode executar este passo a qualquer momento! Não precisa apagar o arquivo .duckdb. Basta abrir ele novamente e executar os comandos abaixo.

No terminal (PowerShell), abra o DuckDB com o arquivo criado (ou já existente):

duckdb datalake_airflow.duckdb

Dentro do shell do DuckDB, execute os seguintes comandos NA ORDEM para instalar a extensão PostgreSQL e copiar os dados:

-- Passo 1: Instalar e carregar a extensão PostgreSQL (executar apenas 1 vez)
INSTALL postgres;
LOAD postgres;

-- Passo 2: Conectar ao PostgreSQL remoto (executar toda vez que abrir o DuckDB)
ATTACH 'host=46.224.156.251 port=25433 dbname=datalake_bi user=pbi_user password=pbi_password' AS pg (TYPE POSTGRES);

-- Passo 3: Agora sim, criar as tabelas locais a partir dos dados remotos
CREATE TABLE delta_artist AS SELECT * FROM pg.public.delta_artist;

-- Sair e salvar
.quit

🚨 CRÍTICO: O comando ATTACH NÃO é salvo no arquivo! Quando você fecha o DuckDB (.quit) e abre novamente, a conexão "pg" é perdida. Você precisa executar o ATTACH novamente antes de criar novas tabelas!

Substitua:

  • 46.224.156.251 pelo IP ou hostname do servidor PostgreSQL (ex: 192.168.1.100 ou meuservidor.com)
  • Se estiver na mesma máquina, use localhost

💡 Dica: Este processo copia os dados do PostgreSQL para o arquivo .duckdb local. Depois disso, você não precisará mais do PostgreSQL para consultar os dados no Power BI.

➕ Adicionar Mais Tabelas

Se precisar adicionar outras tabelas ao mesmo arquivo .duckdb:

  1. Abra novamente o arquivo: duckdb datalake_airflow.duckdb
  2. EXECUTE NOVAMENTE os comandos de conexão:
-- Carregar a extensão (se ainda não foi instalada)
LOAD postgres;

-- SEMPRE executar o ATTACH ao abrir uma nova sessão
ATTACH 'host=46.224.156.251 port=25433 dbname=datalake_bi user=pbi_user password=pbi_password' AS pg (TYPE POSTGRES);

-- Agora criar as novas tabelas
CREATE TABLE delta_invoice AS SELECT * FROM pg.public.delta_invoice;
CREATE TABLE delta_employee AS SELECT * FROM pg.public.delta_employee;
-- ... adicione quantas tabelas precisar

.quit

⚠️ Importante: Se a tabela já existir no .duckdb, você receberá um erro. Para substituir dados existentes, use:
DROP TABLE IF EXISTS nome_tabela; CREATE TABLE nome_tabela AS SELECT * FROM pg.public.nome_tabela;

0.2 Iniciar Servidor DuckDB (SOLUÇÃO para Erro ODBC 08003)

🚨 PROBLEMA COMUM: Ao carregar dados no Power BI você pode receber o erro ODBC 08003 ou "arquivo já aberto". Isso acontece porque múltiplos processos tentam acessar o mesmo arquivo .duckdb simultaneamente.

✅ SOLUÇÃO RECOMENDADA: Conecte direto no PostgreSQL via Power BI (sem ODBC/DuckDB). Pule para o final desta seção!

🐍 Servidor DuckDB via Python

⚠️ Pré-requisito: Instale o módulo Python do DuckDB primeiro: 

pip install duckdb

Crie um arquivo duckdb_server.py na mesma pasta do arquivo .duckdb:

import duckdb
from http.server import BaseHTTPRequestHandler, HTTPServer
import json

# Conectar ao arquivo DuckDB
con = duckdb.connect('datalake_airflow.duckdb', read_only=True)

class DuckDBHandler(BaseHTTPRequestHandler):
    def do_POST(self):
        content_length = int(self.headers['Content-Length'])
        post_data = self.rfile.read(content_length)
        query = json.loads(post_data).get('query', '')
        
        try:
            result = con.execute(query).fetchall()
            columns = [desc[0] for desc in con.description]
            response = {'columns': columns, 'data': result}
            
            self.send_response(200)
            self.send_header('Content-type', 'application/json')
            self.end_headers()
            self.wfile.write(json.dumps(response).encode())
        except Exception as e:
            self.send_response(500)
            self.end_headers()
            self.wfile.write(str(e).encode())

server = HTTPServer(('localhost', 8080), DuckDBHandler)
print("DuckDB Server rodando na porta 8080...")
server.serve_forever()

Execute o servidor:

python duckdb_server.py

  1. Selecione as tabelas desejadas (delta_artist, delta_invoice, etc.)

📊 Import vs DirectQuery

Import (Importar - Padrão):

  • ✅ Melhor performance nas visualizações
  • ✅ Funciona offline
  • ✅ Todos os recursos DAX disponíveis
  • ❌ Precisa atualizar manualmente para ver novos dados
  • ❌ Consome mais memória

DirectQuery (Consulta Direta):

  • ✅ Sempre mostra dados atualizados em tempo real
  • ✅ Não consome memória local (dados ficam no servidor)
  • ✅ Ideal para grandes volumes de dados
  • ❌ Mais lento (cada visualização faz query no banco)
  • ❌ Requer conexão constante com o servidor
  • ❌ Algumas funções DAX não funcionam

💡 Recomendação: Use Import para desenvolvimento e dashboards pequenos/médios. Use DirectQuery para dados que mudam frequentemente ou volumes muito grandes.

  1. Clique em Carregar (Import) ou OK (DirectQuery)

1. Baixar o Driver ODBC

Acesse o link oficial abaixo para realizar o download do driver:

👉 Acesse a Documentação Oficial do DuckDB (ODBC Windows)

Como instalar:

  • 1. Extraia o arquivo ZIP para uma pasta segura.
  • 2. Clique com o botão direito no arquivo duckdb_odbc.inf.
  • 3. Selecione Instalar (Install).
  • 4. Confirme as permissões do Windows.

2. Configurar Fonte de Dados (DSN)

  1. Abra o Administrador de Fonte de Dados ODBC (64 bits).
  2. Na aba DSN de Sistema, clique em Adicionar.
  3. Escolha DuckDB Driver.
  4. No campo Database, informe o caminho do arquivo gerado no Passo 0:
    5. C:\caminho\datalake_airflow.duckdb

3. Conectar no Power BI

⚠️ Importante: DuckDB é um banco baseado em arquivo (não é servidor), portanto NÃO usa porta e NÃO requer autenticação!

O driver ODBC lê o arquivo .duckdb diretamente do disco, sem conexão de rede.

  1. No Power BI Desktop, vá em Obter Dados > ODBC.
  2. Selecione o DSN criado anteriormente.
  3. Clique em Opções Avançadas e insira a instrução SQL:
SELECT * FROM delta_artist;
  1. Na janela de autenticação, selecione Anônimo ou Windows (não precisa de credenciais).

📌 Alternativa - Conexão via PostgreSQL:
Se você preferir conectar diretamente ao PostgreSQL (servidor de banco de dados), use:
Tipo: PostgreSQL (não ODBC/DuckDB)
Servidor: localhost:25433
Usuário: pbi_user
Senha: pbi_password
Database: datalake_bi

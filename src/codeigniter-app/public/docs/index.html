Guia de Uso: Git & dbt Analytics

Aprenda a versionar seus modelos e processar a camada Gold com isolamento completo

Visão Geral

O MyDataFlow integra um editor Monaco unificado com controle de versionamento Git e execução do dbt Core. Com essa stack, os dados brutos salvos no PostgreSQL analítico são limpos, agregados e refinados, transformando-se em cubos e dimensões prontos para visualização no Metabase.

Isolamento de Segurança (Multi-Tenancy)

Cada aluno/inquilino trabalha em schemas exclusivos no PostgreSQL, garantindo que o seu desenvolvimento não afete os dados de outros usuários.

1. Conectando seu Repositório GitHub

Antes de editar ou salvar seus códigos SQL e configurações dbt, você precisa conectar o seu repositório pessoal na barra lateral do Git:

  • 1

    Gerar Token no GitHub

    No seu perfil do GitHub, vá em Settings → Developer settings → Personal access tokens → Tokens (classic). Clique em Generate new token, marque o escopo repo e salve o token gerado.

  • 2

    Vincular no Painel

    Abra o menu Serviços → SQL Editor + Customizações Python, ative a aba 🔗 Git na barra lateral esquerda e insira:

    • GitHub Username: Seu nome de usuário do GitHub.
    • Personal Access Token: O token clássico gerado no passo anterior.
    • Repo URL: O nome do seu repositório público ou privado no formato usuario/nome-do-repositorio.

    Clique em Conectar. O sistema irá clonar a estrutura no servidor e listar seus arquivos.

2. Guia de Uso do dbt no Monaco Editor

O dbt lê dados brutos do schema público (sincronizados pelo Airflow) e materializa tabelas analíticas organizadas. Siga o passo a passo detalhado abaixo para utilizar a interface do Monaco Editor:

  • 1

    Selecionar a Aba dbt Analytics

    No painel do editor de código, clique no botão 📊 dbt Analytics no menu superior de abas. A interface será configurada para carregar o editor Monaco com suporte à sintaxe SQL/YAML e a barra lateral do Git filtrará automaticamente para exibir apenas arquivos .sql e .yml do seu repositório.

  • 2

    Navegar e Abrir Arquivos

    Caso a barra lateral esquerda esteja fechada, clique no botão 📁 GitHub na barra de ferramentas do painel. Navegue pela estrutura de pastas (como models/) e dê um clique no arquivo que deseja editar para carregá-lo no Monaco Editor.

  • 3

    Criar uma Nova Pasta ou Arquivo

    Você pode estruturar seu projeto criando novos diretórios ou arquivos diretamente na barra lateral do Git:

    • Para criar uma pasta: Digite o nome da pasta no campo 📁 Criar Pasta e clique no botão. Ela será criada abaixo do diretório selecionado ou na raiz se nada estiver selecionado.
    • Para criar um arquivo SQL: Selecione a pasta de destino na árvore, digite o nome do arquivo (ex: dim_usuarios.sql) no campo ➕ Criar Novo Arquivo e clique em Criar do Editor.
  • 4

    Escrever e Formatar seu Código SQL

    Edite o arquivo SQL no Monaco Editor central utilizando sintaxe SQL e Jinja. Exemplo de modelo baseado na fonte padrão do lab (raw_lakehouse.customers):

    select 
    customernumber as id_usuario, 
    customername as nome, 
    contactemail as email,
    'Client' as perfil
from {{ source('raw_lakehouse', 'customers') }}

    Uso de Fontes Customizadas (Ex: public.usuario)

    Se você deseja mapear uma fonte diferente do padrão (ex: public.usuario), você deve criar um arquivo models/sources.yml no seu repositório Git com o seguinte conteúdo:

    version: 2
sources:
  - name: public
    tables:
      - name: usuario
  • 5

    Salvar seu Progresso no MinIO

    Após realizar alterações no editor, localize a seção 📝 Arquivo Atual na barra lateral do Git e clique no botão 💾 Salvar. O sistema irá enviar o código alterado para o armazenamento seguro do MinIO e exibirá uma confirmação verde de sucesso.

  • 6

    Executar Comandos dbt e Acompanhar Logs

    Use os botões de controle na barra de ferramentas superior para interagir com o container do dbt:

    • Clique em ▶️ dbt Run (Dev) para compilar e materializar o modelo no seu schema de testes.
    • Os logs detalhados do processamento serão exibidos em tempo real no painel 💻 Terminal dbt Console no canto superior direito.
  • 7

    Gerar e Visualizar a Linhagem

    Clique em 📖 dbt Docs (Dev) na barra superior. Isso dispara a compilação do catálogo de metadados. Assim que concluído, o gráfico interativo de linhagem (Lineage Graph) será renderizado automaticamente no iframe inferior direito, permitindo visualizar o fluxo dos dados visualmente.

3. Testando e Gerando a Linhagem

O console integrado permite rodar os comandos do dbt em contêineres Docker isolados a partir da interface:

  • 1

    Executar em Homologação Dev

    Clique em ▶️ dbt Run (Dev). O dbt compilará seus arquivos e executará a transformação, criando as tabelas e views no seu schema de testes exclusivo: user_{seu_id}_homolog_analytics.

  • 2

    Testar Consistência

    Clique em 🧪 dbt Test (Dev). O dbt executará testes de chaves primárias, integridade referencial e valores nulos declarados no seu arquivo schema.yml.

  • 3

    Visualizar Linhagem (Lineage Graph)

    Clique em 📖 dbt Docs (Dev). O servidor compilará a documentação de linhagem de dados. Assim que finalizado, o **gráfico interativo** será carregado no iframe inferior do painel, permitindo analisar como as tabelas se conectam.

4. Implantando em Produção

Quando seus modelos estiverem validados no ambiente de desenvolvimento, implante-os em produção:

  • 1

    Deploy no Schema de Produção Prod

    Clique no botão ▶️ dbt Run (Prod). Os modelos finais serão consolidados no schema de produção: user_{seu_id}_analytics. O painel do Metabase consome os dados diretamente deste schema.

  • 2

    Sincronizar no GitHub

    Na aba do Git, digite uma mensagem de commit (ex: "feat: adiciona modelo analítico de vendas") e clique em 🚀 Commit & Push. Suas modificações serão enviadas para o seu repositório remoto no GitHub.

💡 Dica para Relatórios

No Metabase, configure sua fonte de dados apontando as queries para as tabelas dentro do seu schema de produção (user_{seu_id}_analytics) para montar gráficos dinâmicos de faturamento, vendas e acessos.
